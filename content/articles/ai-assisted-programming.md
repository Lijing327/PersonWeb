# AI 辅助编程：从 Copilot 到自定义 Agent

过去两年，我写代码的方式变了：从「自己敲每一行」变成「描述意图 → 审阅生成 → 自己把关边界」。工具在变，**责任没变**——线上跑的还是你的代码。

## 工具分层

| 层级 | 代表 | 适合做什么 |
| --- | --- | --- |
| 补全 | Copilot / 内联补全 | 样板代码、测试骨架、重复模式 |
| 对话式编辑 | Cursor / Chat | 跨文件改动、排查、重构说明 |
| Agent | 自定义 Agent / 多步工具调用 | 固定流程：生成静态数据、跑检查、批量改文案 |

越往下，自动化越强，也越需要你写清约束（仓库规范、禁止事项、验证步骤）。

## 我怎么用

### 1. 补全：加速，不替代思考

- 写过一遍的模式（表单校验、API 包装）让补全帮你
- 安全与鉴权相关代码：**自己写或逐行审**
- 生成后立刻跑类型检查 / 相关测试

### 2. 对话：带着上下文提问

差问题：「帮我优化一下这个网站」  
好问题：「`pages/blog/[id].vue` 阅读量不显示，Nitro 在静态托管不可用，请改成静态 JSON 回退」

把路径、现象、约束写清楚，返工会少一半。

### 3. 自定义 Agent：固化重复劳动

对本站有用的自动化例子：

- 批量补全过短的 Markdown 文章
- `generate` 前构建文章静态索引
- 按 AGENTS.md 先读手册再改样式

Agent 适合「步骤固定、可验证」的事；开放式产品决策仍要人来。

## 实践原则

1. **先有验收标准**：怎样算完成？谁来验证？
2. **小步提交**：一次只改一条链路，方便回滚
3. **规范进仓库**：`AGENTS.md`、style 手册比口头叮嘱可靠
4. **敏感操作人工确认**：删数据、改权限、推生产

## 效率从哪里来

AI 省的是「从空白到初稿」的时间；真正拉开差距的是：

- 你能不能快速判断生成结果对不对
- 项目结构是否清晰（AI 才找得到落点）
- 有没有最小验证习惯（跑通再宣称完成）

## 小结

Copilot 是打字机加速，Cursor 是结对程序员，Agent 是流水线工人。三者可以叠加，但**架构、安全、产品取舍**仍要你做主。会用 AI 的人，替代的是「不会用 AI 的自己」。
