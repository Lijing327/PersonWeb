# 创作的过程：从想法到实现

每个上线的功能，最初往往只是一句很轻的话：「要是有个……就好了」。从这句话到用户点得开的页面，中间是一连串取舍。把过程写下来，是为了下次少迷路。

## 阶段 0：想法捕获

- 随手记在备忘，不立刻开仓库  
- 过两天还觉得痒，再进入下一阶段  
- 问自己：这是真需求，还是新鲜感？  

## 阶段 1：收窄范围

写出 **MVP 只做三件事**。个人站早期若贪多，会同时开博客、商城、社区、AI——最后什么都半成品。

好的收窄像这样：「先让文章列表在静态托管上也能显示」，而不是「打造内容中台」。

## 阶段 2：可运行的丑原型

- 能点、能错、能改  
- UI 可以简陋，路径必须真实  
- 尽早部署，暴露环境差异（本地有、线上无之类）  

## 阶段 3：打磨与删除

创作不只是加法。删掉充数菜单、合并重复入口、把文案写人话，常常比再加一个动效更接近「完成」。

## 阶段 4：复盘留资产

- 踩坑写成文章或 README  
- 可复用的抽成组件 / 脚本  
- 记录「为什么不这么做」——未来的自己会感谢  

## 乐趣在哪

卡关很烦，但当一个模糊念头变成链接，那种具体感无可替代。过程充满挑战，也正因为挑战，完成时才像真正造过一样东西。

写给未来的自己：卡住时回到阶段 1，问范围是不是又胀了。大多数创作危机，其实是范围危机。
